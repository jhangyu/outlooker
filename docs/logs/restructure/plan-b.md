## 0. Design principles (why this shape)
1. **Same depth, new name.** `src-tauri/` becomes `backend/` at the same depth. Every Rust path relative to `CARGO_MANIFEST_DIR` (`../../resources/postgresql`, `../../../../schemas/...`, `../../../<repo>`) keeps working without edits. This removes the riskiest class of edits (Rust `include_str!` and fixture paths).
2. **One npm package, at `frontend/`.** Node resolves `node_modules` from the importing file's directory upward. It does not use the cwd. Every file that imports an npm package must therefore sit under the package dir. These files are vite.config, `vitest-capped.mjs` (`import "vite"`), e2e specs (`@wdio/*` types), and wdio.conf. So the e2e suite and the vitest wrapper move into `frontend/`. It is the tooling owner, not only the UI. The alternative is a second package.json for e2e, which means two lockfiles and two `node_modules`. The no-duplicate-modules policy rejects that.
3. **`scripts/` stays at the top level for npm-free repo tooling.** `cargo-test-runner.mjs`, `test-time-judge.mjs` and `fetch-postgres.mjs` import only `node:*` builtins (verified: `scripts/fetch-postgres.mjs:1-11`, `scripts/cargo-test-runner.mjs:4-8`). `backend/.cargo/config.toml:4` (`../scripts/cargo-test-runner.mjs`) and all Rust messages `run node scripts/fetch-postgres.mjs` stay valid unchanged.
4. **Shared fixtures get one top-level home: `fixtures/`.** Both Rust tests and e2e use `tests/fixtures/external/outlook.pst`. After the move, top-level `tests/` would hold only fixtures, so it is renamed to make that explicit.
5. **Root dot-dirs for tool configs:** `.config/mise.toml` and `.claude/CLAUDE.md`. Both locations were checked against tool docs or the binary (section 4).

I could not confirm whether the lookup searches the parent's subtree.
  - Plan: probe with `npx tauri info` (no compile) in the slot.
  - If it fails, add a 5-line `frontend/scripts/tauri.mjs`. It sets `TAURI_APP_PATH=<abs backend>` and spawns the local tauri bin. `package.json:17` becomes `"tauri": "node scripts/tauri.mjs"`, and `e2e/build.mjs:19` uses `npm run tauri --`.
  - Also unverified: the cwd of string-form `beforeBuildCommand`. I assume it is the frontend dir, found by package.json. `e2e:build` checks this.
- **R2 `git mv <dir>` and ignored content.** I expect one `rename(2)` of the directory, so `target/`, `gen/` and `resources/postgresql/` move with it. I did not verify this; the hook blocked my scratch-repo probe. If leftovers stay in `src-tauri/`, plain-`mv` them after confirming the list.
- **R3 cold rebuild.** Workspace crate fingerprints hold absolute paths, and `crates/pff/build.rs` emits an absolute rerun-if-changed (env-traps memory). So the first build recompiles libpff and the workspace crates. Registry deps stay warm if `target/` moved. The 150 s build cap may need 2 repeats.

Only a real `npm run e2e` group run does, and that needs a long-run approval. Cheapest proof: `node e2e/run.mjs --spec e2e/seeded.e2e.ts`, if it fits the cap.
- **R5 Muscle memory and external refs.** Windows SSH checkout steps, the memory files, and `.git/info/exclude` symlink entries in existing worktrees all cite `src-tauri/`. In-flight branches were not inventoried (`git worktree list` not run). A branch that touches `src-tauri/` will conflict heavily after the rename. Check before round 1.
- **R6 superpowers skill.** It writes new specs to `docs/superpowers/specs/` by default. The CLAUDE.md line mitigates this but does not enforce it.
